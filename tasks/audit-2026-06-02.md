### ✅ VERIFIKACIJOS METU RASTAS + IŠTAISYTAS BUG — catalog auth-race (`944636e`)

Po Blocks 1-3, user verifikuodamas rado regresiją: search rodė real foto (ne
watercolor), stale LT vardus (Ilgalapis inkstapaprėtis vietoj Bostono papartis
override), biblioteka kartais tuščia. Console: `[catalog] subscription error:
Missing or insufficient permissions`.

**ROOT CAUSE:** `App.jsx` subscribeCatalog useEffect deps=`[]` → subscription
startuodavo on mount PRIEŠ auth ready → catalog rule (request.auth != null)
denied → subscription mirdavo (NEretry'ino) → `_catalogById` tuščias iki
refresh'o → resolvePlantView neturi overlay → user augalai be heroIllustration.
Tikėtina, kad user'io API key referrer restriction (P0-2) pridėjo auth latency,
praplėtė race window → tapo matomas.

**FIX (944636e):** (1) App.jsx gate subscription on auth `[user?.uid, viewerToken]`;
(2) catalog.js subscribeCatalog bounded retry (4x backoff) permission-denied
atveju. Verifikuota — watercolor + correct LT names + non-empty biblioteka grįžo.

**LESSON:** Firestore client subscriptions VISADA gate'inti on auth-ready
(`request.auth != null` rules). Mount-time `[]` subscription = race su auth.

## P0 — Kritiniai (būtina prieš ką nors kitą)

### P0-1 · JWT signature verification GAP 🔴

**Statusas:** ✅ verifikuotas patikrinant `api/_firestore.js:57`

```js
export function uidFromToken(token) {
  try {
    const payload = JSON.parse(Buffer.from(token.split('.')[1], 'base64').toString('utf8'))
    return payload.sub || payload.user_id || null
  } catch { return null }
}
```

Decode'ina payload'ą be parašo verifikacijos. Bet kas gali forge'inti JWT su norimu `sub`/`user_id` → bypass'ina ALL auth checks.

**Exploit chain (admin escalation):**
1. Attacker decode'ina realaus admin'o token'ą iš JS bundle'o (Firebase API key matomas)
2. Sukuria fake JWT: `{ "sub": "<admin_uid>", "user_id": "<admin_uid>", "iss": "irrelevant" }` + base64 encode + dummy sig
3. POST `/api/save-plant` su `Authorization: Bearer <fake>` + tuščiais `plantId`/`colId` (admin mode trigger)
4. `uidFromToken` extract'ina admin UID → `isUidAdmin(uid)` skaito Firestore `users/{admin_uid}.isAdmin` → `true`
5. Attacker pasiekia admin endpoint'ą + gali rašyti į catalog'ą

**Fix:**
- Pakeisti `uidFromToken` į `await admin.auth().verifyIdToken(token)` per Firebase Admin SDK
- Šitas verifikuoja parašą + expiration + issuer
- Affected endpoints (visi): `save-plant`, `generate-hero`, `rehost-image`, `claude`, `plant-image`, `dev-toxicity-test`

**Effort:** ~30 min. Vienos funkcijos pakeitimas + visų endpoint'ų signature update (await + try/catch).

### P0-4 · Catalog stuck mid-pipeline (OOM scenario)

**Vieta:** `api/save-plant.js` viso processPlant'o flow

Jei Vercel function OOM'inasi tarp narrative write + hero finish, catalog turi `enrichmentStage: 'narrative'` permanent. `phase2CompletedAt` neužrašytas. Naujas listener'is detect'ina kaip „in-progress" ir niekada nevaldys to entry's.

**Fix opciono A:** Atomic write — pakeisti į `try { ... await Promise.all([heroPromise, textPipeline]) } finally { writeStage('complete' or 'failed') }`. Garantuoja, kad final stage'as visada užrašomas.

**Fix opcijos B:** Recovery script — periodinė Cloud Function, kuri tikrina `enrichmentStage != complete|failed && enrichmentUpdatedAt > 5min ago` → write'ina 'failed' su error reason "stale enrichment, likely OOM".

**Effort:** Opciono A — ~30 min. Opciono B — ~1h (extra serverless function setup).

**Rekomendacija:** A (atomic) + lightweight B (Cloud Function) defense-in-depth.

### P0-5 · Idempotency race admin mode'e

**Vieta:** `api/save-plant.js:198`

Du admin'ai paspaudžia „+AI" tuo pat metu → abu skip'ina idempotency check'ą → abu rašo catalog/{slug} → nondeterministic last-write-wins.

**Fix:** Per-document advisory lock per Firestore transaction:

```js
// Pradžioje processPlant:
const lockRef = adminFirestore().collection('catalog').doc(slug)
const lockResult = await adminFirestore().runTransaction(async tx => {
  const doc = await tx.get(lockRef)
  const lock = doc.data()?._enrichmentLock
  const now = Date.now()
  // Atmetam jei kitas pipeline'as vyksta < 5 min
  if (lock && (now - new Date(lock.at).getTime()) < 5 * 60 * 1000) {
    return { acquired: false, by: lock.uid }
  }
  tx.set(lockRef, { _enrichmentLock: { uid, at: new Date().toISOString() } }, { merge: true })
  return { acquired: true }
})
if (!lockResult.acquired) {
  console.log('[save-plant] lock'as užrakintas (kitas admin re-enrich'ina)', { by: lockResult.by })
  await writeStage('failed', { enrichmentError: `Lock'as užrakintas (admin: ${lockResult.by})` })
  return
}
// Pabaigoje (finally) — release lock
finally {
  await lockRef.set({ _enrichmentLock: null }, { merge: true })
}
```

**Effort:** ~45 min.

### P0-7 · SSRF rehost-image'e

**Vieta:** `api/rehost-image.js:100`

Endpoint'as fetch'ina arbitrary HTTPS URL'us iš client'o. Nėra apsaugos nuo:
- AWS/GCP metadata endpoints (`169.254.169.254`, `metadata.google.internal`)
- Private IP ranges (`127.0.0.1`, `10.*`, `192.168.*`, `172.16-31.*`)
- localhost aliases

**Exploit chain (GCP token theft):**
1. Attacker POST `/api/rehost-image { url: "http://metadata.google.internal/computeMetadata/v1/instance/service-accounts/default/token" }`
2. Server'is fetch'ina iš metadata service (because Vercel may run on GCP)
3. Response — service account JWT
4. Server'is rehost'ina jį į Storage kaip JPEG
5. Public URL'as su token'u → exfiltration

**Fix:**

```js
function isUrlSafe(url) {
  try {
    const u = new URL(url)
    if (!['http:', 'https:'].includes(u.protocol)) return false
    // Block metadata endpoints
    if (/^(169\.254\.|metadata\.|127\.|localhost|0\.0\.0\.0)/i.test(u.hostname)) return false
    // Block private IPs (basic regex; for production use net.isIP + range check)
    if (/^(10\.|192\.168\.|172\.(1[6-9]|2\d|3[01])\.)/.test(u.hostname)) return false
    return true
  } catch { return false }
}

// Pradžioje:
if (!isUrlSafe(url)) return res.status(400).json({ error: 'unsafe URL' })
```

**Effort:** ~20 min.
